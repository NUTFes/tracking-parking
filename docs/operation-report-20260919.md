## 1. 既定では録画されない

`scripts/run_production.sh` の `DETECT_ENV` 既定は `jetson-newcam.env` で、その中に
`SAVE_VIDEO=false` がある。比較条件を固定するためのファイルなので当然だが、結果として
**runbook どおりに起動すると録画されない。**

runbook「3. 起動」の期待表示は `録画: 有効 / 256MBごと / 空きXXXGB` だが、実際に出るのは
`録画: 無効（SAVE_VIDEO=false）` である。当日は run 1 をこの状態で1時間46分動かしてしまった。

録画するには環境変数で上書きする。`load_dotenv()` は `override=False` なので、
プロセス環境が `.env` の値に勝つ。

```bash
SAVE_VIDEO=true scripts/run_production.sh
```

起動直後にこの2行が出ていなければ録画されていない。

```
✓ 出力動画: .../videos/camera_YYYYMMDD_HHMMSS/segment_%05d.mp4 (encoder=nvenc)
  分割: 256MBごと / 本数制限なし / 空きXXXGB
```

**tmux で `send-keys` を使って起動するときは、入力行に打ちかけの文字が残っていないか
確認すること。** run 2 はこれで失敗した。ペインに残っていた `ls` と連結して
`lsSAVE_VIDEO=true scripts/run_production.sh` になり、`SAVE_VIDEO` ではない別名の変数が
設定された状態で起動していた。事前チェックの「録画: 無効」で気づいて止めた。
`C-u` で行を消してから送り、Enter の前に `capture-pane` で内容を確かめる。

## 2. カメラが2回動いた

固定が甘く、運用中に動いた。**1回目は 12:00:10 に1フレームで切り替わっている**
（`camera_20260919_095454/segment_00003.mp4` の frame 13490、焼き込み Frame 60909）。
徐々にずれたのではない。2回目は 13:40〜14:11 のあいだ。

ライン座標は設定時の画角に紐づくため、動いた時点で検知は成立しなくなる。実際、
1回目以降は緑の Line1 が窓のサッシの上に乗り、通路を横切らなくなった。

| 区間 | 入庫 | 出庫 | 状態 |
|---|---|---|---|
| 09:54–12:00（2時間6分） | 174 | 61 | 正常 |
| 12:00–14:27（2時間27分） | 3 | 11 | **ほぼ検知できていない** |

例外が出るわけではなく、イベントが静かに減るだけなので、ログを見ているだけでは
気づけない。当日は録画フレームを確認して初めて分かった。

**カメラを動かしたら、戻したつもりでも元の画角には戻らない。** 14:28 に手で戻したあとの
画角は、今朝の画角と比べて景色全体が約60px下にずれていた（カメラがわずかに上を向いた
状態）。それでも Line1 は通路を横切り、Line2 は駐車場側にあったため、run 4 のカウントは
成立している。厳密に合わせるならライン座標を取り直す。

## 3. 画角のずれは録画フレームの差分で検知できる

当日の実測から、画角が動いたかどうかは単純な輝度差分で判定できることが分かった。
グレースケール化して 160x90 に縮小し、焼き込みオーバーレイ（左上 360x200）を除いた
平均二乗誤差を使う。

| 条件 | 直前セグメントとの差 | 先頭セグメントとの差 |
|---|---|---|
| 日照変化のみ（09/18 15:18→18:07、日没をまたぐ・カメラ固定） | 最大 1680 | 最大 1870 |
| 実際の移動（1回目） | **9402** | 9560 |
| 実際の移動（2回目） | **3147** | — |

桁が分かれるので、**直前との差が 2500 以上なら「直近で動いた」、先頭との差が 4000 以上なら
「ずれたまま」**と判定できる。2つ併用するのは、先頭との差だけだと日照変化で誤検知し、
直前との差だけだとゆっくりしたずれを見逃すため。

位相相関によるピクセル単位のずれ量は使えなかった。カメラの動きが並進ではなく向きの
変化のため、相関のピークが立たない（応答値 0.04〜0.09）。

当日は30分間隔でこの判定を回し、17:17 の停止まで run 4 の画角は安定していた
（先頭との差 183〜450）。

## 運用時に効いた制約

- **書き込み中のセグメントは読めない**（`moov atom not found`）。画角の確認は常に
  確定済みの最新セグメントを見る。確定は256MBごと＝約32分間隔
- **`events_*.csv` の `timestamp_sec` から実時刻は復元できない。** run 4 では最大2694秒に
  対して実稼働9910秒だった。公称30fpsでフレーム番号を割っているため
  （[ADR 0003](decisions/0003-camera-input-and-recording.md) の既知の課題）。時刻が要るときは
  フレームに焼き込まれた JST を読む
- **カメラは1プロセス排他。** 稼働中は `preview_camera.py` も `setup_lines.py` も開けない。
  画角を見るには検知を止める必要がある
- **tmux でペインを閉じて止めてはいけない。** SIGHUP になり `finally` を通らないため、
  書きかけセグメントの moov が書かれず、イベントログも保存されない。`kill -9` と同じ
  壊れ方をする。停止は必ず `kill -INT <python本体のPID>`
